Task<string> vs Task.Run()
=========================================
Task (from System.Threading.Tasks) is a class that represents an asynchronous operation — some unit of work that 
may still be running, may complete in the future, and will eventually produce a result (or just complete, if it's non-generic).

Task<string> means there is async process or promise that some taks will be completed in sometime and will return string.

Key Nuances & Details to Keep in Mind:
---------------------------------------
Returning Data: Task.Run returns a Task or Task<T>. To get the data back, you use await on the task (e.g., var result = await Task.Run(() => ComputeSomething());).

1. CPU-Bound vs. I/O-Bound:

    Task.Run is designed for CPU-bound work (heavy calculations, image processing, cryptography) where you want to shift work off the main thread.

2. For I/O-bound work 
    (like reading files, querying databases, or making HTTP requests), you should not wrap it in Task.Run. 
    Those operations are already asynchronous natively (e.g., HttpClient.GetAsync()), and wrapping them in Task.Run 
    just wastes a ThreadPool thread waiting for the I/O to finish.

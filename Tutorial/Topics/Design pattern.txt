    2. Factory pattern:
        In Factory pattern, object are created in specialized class. Instead of using the new keyword directly in any class
        we request the factory class to provide the object.
        Suppose we have payment service which handles UPI payment, credit card, debit card.
        so Payment service should not directly create the different payment method class and call the pay.
        Instead Controller will call the PaymentFactory class which returns IPayment instance.
        PaymentFactory will have GetPaymentService => type == 'UPI' then new UpiPaymentService();
        UpiPaymentService implements IPaymentService having void pay() method.
        
        For this we need Interface for the actual task, like IPaymentService.
        Different Concrete class like UpiPayment, CreditCardPayment implementing interface IPaymentService
        Single Factory class which returns the new objects based on type using if else or switch case.
        Single factory violates the open closed principle and does nto adhere solid principle
        Separate factory for each service like CreditPaymentFactroy, UpiPaymentFactory
        For this define IPaymentFactory interface which will be implemented by above concrete class.
        Each factory will return the actual payment service class. 

        To decide which factory to call, 
        Use AddKeyedTransient<IPaymentFactory, UpiPaymentFactory>("upi");
        AddKeyedTransient<IPaymentFactory, CreditCardPaymentFactory>("cc");
        in method:
            makePayment([FromKeyedService("upi") IPaymentFactory UpiPayment])
        
        When object creation is little complex and involves multiple checks then better to define factory for separation of concerns.

        True factory method pattern example:
        // --------------------------------------------------
            // 1. PRODUCT INTERFACES & CLASSES
            // --------------------------------------------------
            // The abstract product or interface that defines the output
            public interface IDocument
            {
                void PrintFormat();
            }

            // Concrete Product A
            public class PdfDocument : IDocument
            {
                public void PrintFormat() => Console.WriteLine("Rendering PDF layout...");
            }

            // Concrete Product B
            public class WordDocument : IDocument
            {
                public void PrintFormat() => Console.WriteLine("Rendering Microsoft Word layout...");
            }

            // --------------------------------------------------
            // 2. CREATOR CLASSES (THE INHERITANCE CORE)
            // --------------------------------------------------
            // Base Creator class utilizing inheritance
            public abstract class DocumentCreator
            {
                // The Factory Method - must be implemented or overridden by subclasses
                public abstract IDocument CreateDocument();

                // Core business logic operates on the abstraction, not the concrete classes
                public void ProcessDocument()
                {
                    IDocument doc = CreateDocument(); // Calls the overridden method in the subclass
                    doc.PrintFormat();
                }
            }

            // Subclass Creator A
            public class PdfCreator : DocumentCreator
            {
                // Overriding the base factory method via inheritance
                public override IDocument CreateDocument()
                {
                    return new PdfDocument();
                }
            }

            // Subclass Creator B
            public class WordCreator : DocumentCreator
            {
                // Overriding the base factory method via inheritance
                public override IDocument CreateDocument()
                {
                    return new WordDocument();
                }
            }

            // --------------------------------------------------
            // 3. CLIENT EXECUTION
            // --------------------------------------------------
            public class Program
            {
                public static void Main()
                {
                    // Client interacts with the base class but instantiates a specific subclass
                    DocumentCreator creator;

                    // Choose PDF via inheritance
                    creator = new PdfCreator();
                    creator.ProcessDocument(); // Outputs: Rendering PDF layout...

                    // Choose Word via inheritance
                    creator = new WordCreator();
                    creator.ProcessDocument(); // Outputs: Rendering Microsoft Word layout...
                }
            }

    1. Adapter pattern:
    =======================
        When two interfaces are not compatible to work together we can create a Adapter Class which bridges the agp between both.
        The Adapter Design Pattern is a structural pattern that allows two incompatible interfaces to work together.

        Suppose We have one Legacy class which process data in xml format and our modern class is using json format.
        So, instead of changing the Legacy or Modern class better we can create an Adapter class which contains the Legacy class.
        Adapter class will have Legacy class instance and it will call the legacy class method and fecth the data,.
        Now the xml data will be converted into json format and returned the same.

        From uses, 
        create the Legacy class object and pass it to the Adapter class to create the object.
        Now call the Adapter class method to get json data. 
        so using legacy class we didnt change the system and just converting the result into required formatr.
        Here its Has-A relationship and an example of Open-closed principle.

        Best for legacy or 3rd party Api call.

3. Behavioural
    1. Strategy pattern 
    ================================
        To build the Strategy pattern, you need exactly three components:
        
        The Strategy Interface: 
        Defines the action.
        Concrete Strategies: 
        Classes that implement the interface with different behaviors.
        
        The Context: 
        The class that uses the strategy and can switch between them at runtime.

        1. Interface
            public interface IPaymentStrategy
            {
                void Pay(decimal amount);
            }

        2. Concrete Class
            public class CreditCardPayment : IPaymentStrategy
            {
                public void Pay(decimal amount)
                {
                    Console.WriteLine($"Paid {amount} using Credit Card");
                }
            }

            public class PayPalPayment : IPaymentStrategy
            {
                public void Pay(decimal amount)
                {
                    Console.WriteLine($"Paid {amount} using PayPal");
                }
            }
        
        3. Composition in context
            public class ShoppingCart
            {
                private readonly IPaymentStrategy _paymentStrategy;

                public ShoppingCart(IPaymentStrategy paymentStrategy)
                {
                    _paymentStrategy = paymentStrategy;
                }

                public void Checkout(decimal amount)
                {
                    _paymentStrategy.Pay(amount);
                }
            }
        
        uses
        -------
            IPaymentStrategy payment = new CreditCardPayment();
            ShoppingCart cart = new ShoppingCart(payment);
            cart.Checkout(500);


    2. Observer Design Pattern
    =================================
    The Observer Pattern is a behavioral design pattern where one object (the Subject) automatically notifies multiple 
    dependent objects (Observers) whenever its state changes.

    Youtube Subscription-> send video upload alerts to all Subscrbers.


        // ---------------Observer Interface----------------
        public interface IOrderObserver
        {
            void Update(Order order);
        }

        // ---------------Concrete Observers---------------
        public class EmailNotification : IOrderObserver
        {
            public void Update(Order order)
            {
                Console.WriteLine($"Email: Order {order.OrderId} confirmation sent.");
            }
        }

        public class SmsNotification : IOrderObserver
        {
            public void Update(Order order)
            {
                Console.WriteLine($"SMS: Order {order.OrderId} confirmation sent.");
            }
        }

        public class WhatsAppNotification : IOrderObserver
        {
            public void Update(Order order)
            {
                Console.WriteLine($"WhatsApp: Order {order.OrderId} confirmation sent.");
            }
        }

        // ---------------Subject--------------- // Composition : OrderService compose all observer objects.
        public class OrderService
        {
            private readonly List<IOrderObserver> _observers = new();

            public void Subscribe(IOrderObserver observer)
            {
                _observers.Add(observer);
            }

            public void Unsubscribe(IOrderObserver observer)
            {
                _observers.Remove(observer);
            }

            public void CreateOrder(Order order)
            {
                Console.WriteLine($"Order {order.OrderId} created.");

                // Notify all observers
                foreach (var observer in _observers)
                {
                    observer.Update(order);
                }
            }
        }

        public class Order
        {
            public int OrderId { get; set; }
        }

        ------------------------------Execution------------------------------
        class Program
        {
            static void Main()
            {
                var orderService = new OrderService();

                // Register observers
                orderService.Subscribe(new EmailNotification());
                orderService.Subscribe(new SmsNotification());
                orderService.Subscribe(new WhatsAppNotification());

                // Create Order
                var order = new Order { OrderId = 101 };

                orderService.CreateOrder(order);
            }
        }
